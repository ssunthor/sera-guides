# Assets Storage Overview

## Overall Purpose

This `/assets` directory serves as the local storage area during development for various non-database files required or generated by the AI Assistant (SERA/GIA). This includes ingested source documents, extracted images, code snippets for analysis, temporary files, and potentially cached data.

## Kubernetes Mapping [CRITICAL]

In the target Kubernetes environment (within the `sera-ai` namespace), the **entire contents and structure of this `/assets` directory will reside on a shared Persistent Volume Claim (PVC)** named `ai-shared-assets-pvc` (name to be decided later).

This PVC MUST be configured with **`accessModes: [ReadWriteMany]`** (using the RWX-capable NetApp Trident NFS StorageClass) to allow simultaneous access from different pods (like Ingestion Pipelines and Tool Pods).

All relevant pods in Kubernetes will mount this PVC at the **`/assets`** mount point. Therefore, a local path like `/assets/images/some_image.png` will directly correspond to `/assets/images/some_image.png` within the container's filesystem in the Kubernetes deployment.

---

## Subdirectory Structure & Purpose

* **`/assets/cache/`**
    * **Purpose (Local):** Stores semi-persistent cached data generated by tools or processes that might be reusable across runs but isn't core source material (e.g., intermediate analysis steps, downloaded non-essential resources). Content *should* be regenerable if deleted.
    * **K8s Equivalent:** `/assets/cache/` on the shared PVC.

* **`/assets/code/`**
    * **Purpose (Local):** Stores copies of code files or snippets downloaded or extracted for analysis by tools like `code_analyst_tool`. This is the raw source code *before* analysis results are stored in PostgreSQL.
    * **K8s Equivalent:** `/assets/code/` on the shared PVC.

* **`/assets/docs/`**
    * **Purpose (Local):** Stores ingested documents in their original format (e.g., `.docx`, `.txt`, potentially converted `.md`) if direct access to the original file is needed alongside the processed chunks in the VDB/metadata in PSQL.
    * **K8s Equivalent:** `/assets/docs/` on the shared PVC.

* **`/assets/images/`**
    * **Purpose (Local):** Stores image files (e.g., `.png`, `.jpg`) extracted from sources like Confluence. These are the raw image binaries referenced by metadata in PostgreSQL.
    * **K8s Equivalent:** `/assets/images/` on the shared PVC.

* **`/assets/pdfs/`**
    * **Purpose (Local):** Stores ingested PDF documents in their original format if direct access is needed.
    * **K8s Equivalent:** `/assets/pdfs/` on the shared PVC.

* **`/assets/tmp/`**
    * **Purpose (Local):** Intended for strictly temporary, short-lived files generated and cleaned up during the execution of a single tool or process run (e.g., temporary file conversions, intermediate processing artifacts). Content here is generally considered safe to delete between runs. *Could potentially be combined with `/cache/` if this distinction isn't useful.*
    * **K8s Equivalent:** `/assets/tmp/` on the shared PVC. (Note: For truly ephemeral, pod-local temporary storage *not* needing persistence or sharing, Kubernetes pods can use `emptyDir` volumes, which are distinct from this shared PVC location).

* **`/assets/xlsx/`**
    * **Purpose (Local):** Stores ingested Excel spreadsheets (`.xlsx`, `.xls`) in their original format if direct access is needed.
    * **K8s Equivalent:** `/assets/xlsx/` on the shared PVC.

* **`/assets/logs/`**
    * **Purpose (Local):** Stores full logs from individual modules/applications.
    * **K8s Equivalent:** Will be replaced with K8 Logging features.

---

**IMPORTANT:** Ensure that code interacting with these files locally uses relative paths starting from the `/assets` root or constructs paths dynamically based on a configurable base path to facilitate the transition to the `/assets` mount point in Kubernetes. Metadata stored in PostgreSQL should contain the path *relative* to `/assets` (e.g., `images/my_image.png`)
